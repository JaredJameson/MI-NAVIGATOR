```json

  "enabled": true,
  "autoAllowBashIfSandboxed": true
}
```

- Playwright MCP browser runs in sandboxed/containerized environment
- Browser's `localhost` ≠ Host machine's `localhost`
- Network isolation prevents browser→backend communication
- Frontend works because it's served from same Next.js process

### Option B: Create Next.js API Proxy

**What:** Add Next.js API routes that proxy all backend requests

**Implementation:**
```typescript
// app/api/proxy/[...path]/route.ts
export async function GET(req: Request, { params }) {
  const backendUrl = 'http://localhost:8004/api/v1'
  const response = await fetch(`${backendUrl}/${params.path.join('/')}`, {
    headers: {
      ...Object.fromEntries(req.headers),
      'X-Forwarded-For': req.headers.get('x-forwarded-for') || 'unknown'
    }
  })
  return new Response(response.body, {
    status: response.status,
    headers: response.headers
  })
}

// Similar for POST, PUT, DELETE, PATCH
```

**Update frontend:**
```typescript
// .env.local
NEXT_PUBLIC_API_URL=http://localhost:3000/api/proxy
```

**Pros:**
- Doesn't depend on Playwright configuration
- Browser calls same-origin endpoints (no CORS)
- Works immediately

**Cons:**
- Adds complexity (extra network hop)
- Need to implement all HTTP methods (GET, POST, PUT, DELETE, PATCH)
- Need to proxy headers, cookies, streaming responses
- 50+ backend endpoints to handle
- Ongoing maintenance as API changes
- Not a "true" end-to-end test (extra layer)

**Estimated Time:** 2-4 hours
