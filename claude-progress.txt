## Technical Notes

### 404 Error Handling Pattern

**Problem Identified:**
- Previous implementation treated all non-ok HTTP responses identically
- No distinction between 404 (not found), 403 (forbidden), 500 (server error), etc.
- Generic error message didn't inform users if report was deleted vs. other issues

**Solution Implemented:**
1. Check `response.status === 404` before generic error handling
2. Throw specific error message for 404: "Raport nie został znaleziony. Mógł zostać usunięty."
3. Catch block checks error message to preserve specific 404 message
4. Fallback to generic error for other HTTP errors

**Benefits:**
- Users know if report was deleted/doesn't exist (404) vs. other errors
- Better UX - clear communication about what went wrong
- Easier debugging - specific error messages
- Extensible pattern - can add more status-specific handling (403, 401, etc.)

**Future Enhancements:**
- Could add 403 handling: "Nie masz dostępu do tego raportu"
- Could add 401 handling: Auto-redirect to login
- Could add 500 handling: "Błąd serwera - spróbuj później"
