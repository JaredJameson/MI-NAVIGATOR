## Technical Insights

### CSRF Protection Architecture
- Backend uses CSRFMiddleware (app/core/csrf.py)
- Validates `X-CSRF-Token` header for unsafe methods (POST/PUT/DELETE/PATCH)
- Token obtained from `/api/v1/auth/csrf-token` endpoint
- Exempt paths configured in app/main.py (lines 117-131)
- `/api/v1/tags/` is NOT exempt, requires CSRF protection

### Pattern for CSRF-Protected Requests
```typescript
const csrfToken = await getCsrfToken()
if (!csrfToken) throw new Error('Failed to get CSRF token')

const response = await fetch(url, {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${token}`,
    'Content-Type': 'application/json',
    'X-CSRF-Token': csrfToken,  // ← Required!
  },
  body: JSON.stringify(data)
})
```
