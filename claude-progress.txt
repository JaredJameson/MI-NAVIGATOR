## Root Cause Analysis

### The Bug

**Location:** `/backend/app/api/v1/endpoints/chat.py` (WebSocket handler)

**Problem:** When user confirmed research plan, `content` variable was overwritten with research objective, losing original query with NIP.

```python
# BEFORE FIX (Line 2624):
if plan_action == "confirm":
    content = conv["brief"].get("objective", content)  # ❌ WRONG!
    # Result: content = "Podstawowa weryfikacja firmy"
    # Lost: "Lookup company with NIP: 5170359498"
```

**Impact:**
- `generate_mock_response()` received research objective instead of original query
- NIP pattern matching failed
- System returned generic fallback message
- **ALL company lookups broken**

---

## The Fix

### Changes Made

**File:** `backend/app/api/v1/endpoints/chat.py`

**Change 1 - Save original query (Line 2667):**
```python
if is_new_research and "brief" not in conv:
    conv["brief"] = {}
    conv["original_query"] = content  # ✅ NEW - Save for later
```

**Change 2 - Restore original query (Lines 2623-2627):**
```python
if plan_action == "confirm":
    if conv.get("original_query"):
        content = conv["original_query"]  # ✅ FIXED - Use original
    conv["research_confirmed"] = True
```

**Total Changes:** +3 lines in 2 locations

## Key Learnings

### Why Regression Happened:
1. Plan confirmation code assumed brief objective was sufficient
2. No preservation of original user query containing identifiers (NIP, URL, etc.)
3. Code path for "Lookup company" skips brief but fix was needed for other paths

### Prevention Strategy:
1. **Always preserve original user query** when collecting additional info
2. **Use original query for routing/pattern matching**, not derived fields
3. **Test full end-to-end flows** including brief collection paths
4. **Regression tests must cover multiple entry points** (direct lookup vs. research queries)
