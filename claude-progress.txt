## Key Findings

### File Type Validation Best Practices
- ✅ Always include list of supported types in error messages
- ✅ Be specific about what's wrong (show the rejected type)
- ✅ Three layers of protection:
  1. HTML accept attribute (`.pdf,.docx,...`) - first line of defense
  2. JavaScript MIME type validation - prevents bypasses
  3. Backend validation - final security check
- ✅ Error messages should be actionable (tell user what to do)
- ✅ Consistent messaging across UI (button, error, tooltip)

### Error Message UX
- **Bad:** "File type not supported"
- **Good:** "File type 'text/plain' is not supported. Supported types: PDF, DOCX, XLSX, CSV, PNG, JPG."
- ✅ Show what was rejected (the actual MIME type)
- ✅ List ALL supported alternatives
- ✅ Use clear, non-technical language when possible
- ✅ Keep format names short (PDF not "application/pdf")

### Testing Strategy
- ✅ Create test files in browser memory (no filesystem needed)

- ✅ Verify error messages are visible and persistent

### ✅ Feature #133: File upload size validation - PASSED

Fixed critical bug where error messages were cleared immediately after being set, preventing users from seeing validation errors.

**Bug Discovered:**
- `setError()` was called when file > 50MB (line 676)
- `setError('')` was ALWAYS called after forEach (line 689)
- Result: Error message appeared for 1ms then disappeared

**Bug Fix:**
```typescript
// BEFORE (buggy)
Array.from(files).forEach(file => {
  if (file.size > maxSize) {
    setError(`File ${file.name} is too large. Max size is 50MB.`)
    return  // Only exits forEach, not function
  }
})
setError('')  // ALWAYS clears error!

// AFTER (fixed)
let hasError = false
Array.from(files).forEach(file => {
  if (file.size > maxSize) {
    setError(`File ${file.name} is too large. Max size is 50MB.`)
    hasError = true
    return
  }
})
if (!hasError) {  // Only clear if no errors
  setUploadedFiles(prev => [...prev, ...validFiles])
  setError('')
}
```
