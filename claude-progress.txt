## Technical Notes

### Date Picker Implementation Pattern

**Best Practice:**
```typescript
// ❌ Bad: Empty default
const [date, setDate] = useState('')

// ✅ Good: Sensible default with lazy initialization
const [date, setDate] = useState(() => {
  return new Date().toISOString().split('T')[0]
})
```

**Benefits of Lazy Initialization:**
- Function runs only once on mount
- Prevents unnecessary recalculations on re-renders
- Clean, readable code
- Date is always current at component mount time

**Date Validation:**
```typescript
// Prevent future dates
max={new Date().toISOString().split('T')[0]}

// Could also set minimum (if needed)
min="2020-01-01"
```

### Archive Functionality Architecture

**Backend (reports.py):**
- `is_archived` field in report model
- `/api/v1/reports/{id}/archive` endpoint (POST)
- `/api/v1/reports/{id}/unarchive` endpoint (POST)
- Query parameter: `?archived=true/false`
- Default filter: shows only non-archived (`archived=false`)

**Frontend (reports page):**
- Filter buttons: 📊 Wszystkie, 📝 Szkice, ⏳ W trakcie, ✅ Zakończone, 📦 Archiwum
- URL reflects filter state: `/reports?archived=true`
- Active button highlighted with different background
- Archive exists ONLY for reports (not for projects)

**Why Projects Don't Have Archive:**
- Projects use different lifecycle (active vs. completed)
- Reports can be archived when no longer relevant
- Design decision - may be added to projects in future
